# Spec：Web（手机浏览器）窄视口布局适配

## 背景

局域网 Web 访问（`packages/server` 提供 HTTP/WS + Web 静态托管）已可用，但手机打开后是**桌面双栏压缩版**：
- 侧栏占 `max-w-[50%]`（393px 视口下 197px），聊天列有 `min-w-[320px]`，两者相加 517px > 393px；
- 外层容器 `overflow-hidden`，超出部分被**裁切且无法横向滚动**，输入框/欢迎语被切掉；
- 侧栏显隐按钮只存在于桌面专用 `DesktopTopOverlay`；`WorkspaceSidebar` 的 `onToggleSidebar` 是未使用的死参数，`WorkspaceShellLayout` 传了但侧栏内部忽略 → **手机上没有任何收起侧栏的入口**；
- 原移动端形态（单列 + 抽屉）随"手机远控"功能一起被删除（`ZCodeAgentPresentationSurface` 现只剩 `"desktop"`，UI 无任何视口宽度布局判定）。

## 行为规则

1. **窄视口判定**：视口宽度 ≤ 768px 视为窄视口（手机/小屏浏览器）。宽视口行为完全不变（含侧栏可拖拽宽度与其持久化）。
2. **窄视口默认收起侧栏**：进入窄视口时侧栏收起，聊天列占满宽度，不再发生裁切。
3. **窄视口下侧栏是覆盖抽屉**：
   - 打开时覆盖在内容之上（绝对定位、宽度 `min(85vw, 320px)`），不挤压内容；
   - 背后有半透明遮罩，点遮罩关闭；
   - 选中任务后自动关闭（避免留在抽屉里看不到会话）。
4. **窄视口有可见的开启入口**：侧栏收起时，内容区左上角显示悬浮的"切换侧边栏"按钮（复用现有 i18n `workspaceSidebar.toggleSidebar`）。
5. **视口跨越断点**：变窄 → 自动收起；变宽 → 恢复显示（回到桌面双栏）。用户手动切换在断点不变时不被覆盖。

## 状态所有者与边界

- 视口宽度：`hooks/useNarrowViewport.ts`（matchMedia，无状态共享 store；shell 与 panels 各自订阅同一媒体查询）。
- 侧栏显隐唯一所有者仍是 `useAppPanels` 的 `isSidebarVisible`；断点跨越时由它重置为平台默认，不新增第二份可见性状态。
- 抽屉的视觉呈现（覆盖定位/遮罩/悬浮按钮）只属于 `WorkspaceShellLayout`，不进入 store。
- 不改动 `WorkspaceSidebar` 内部结构，也不复活已删除的移动端远控构建（`/remote` 路由、relay）。

## 验收场景

1. 393×852（手机）打开 Web：内容占满宽度，输入框完整可见，无横向裁切。
2. 手机点左上角悬浮按钮：侧栏作为抽屉覆盖出现，点遮罩或选中任务后关闭。
3. 桌面窗口（宽视口）：与改动前一致——侧栏仍是可拖拽的列，宽度持久化生效。
4. 桌面窗口从 >768px 缩小到 <768px：侧栏自动收起；放大回去：恢复显示。
