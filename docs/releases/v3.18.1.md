## 本版改动：跨端同步（specs/web-mobile-cross-process-sync.md）

桌面端与 Web/手机端是两个独立进程、各自一套 Agent 运行时，此前只共享 SQLite 数据库——
运行状态与流式内容都是进程内存态，从不跨进程，导致两端各看各的。本版分三层修复：

### 1. 桌面端变更实时可见（第二阶段）

- 共享任务索引与会话库的跨进程变更通知（`PRAGMA data_version` 轮询 + 去抖）：一端新建/修改任务，
  另一端的侧栏数秒内自动更新，无需手动刷新页面。
- 新增 `v4/conversation/refresh` 协议方法：检测到另一进程写入会话库后，本端重新水合并把新快照
  推给已订阅的客户端——会话后续内容（AI 回复、工具结果）在另一端持续补齐。
- 双向生效：桌面发起手机可见，手机发起桌面可见。
- 修复历史库中 `state` 缺失的 tool part 行导致整个会话水合失败的崩溃。

### 2. 运行状态实时化（第三阶段：运行动画）

- 驱动任务的进程把「运行中 + 心跳」写进共享任务索引（3 秒一跳，任务结束清除）。
- 两端侧栏统一判定：本端实时状态优先，其次**新鲜心跳**（15 秒内）同样显示旋转动画——
  另一端正在跑的任务，本端数秒内出现动画，与桌面端表现一致。
- 心跳过期自动回落：进程崩溃后最多 15 秒停止转圈，历史任务不会永久假转。

### 3. 流式内容准实时（第三阶段：thinking/正文镜像）

- 模型生成期间以约 1 秒节流把已累计的正文与 thinking 落库为「进行中」标记的部分；
  另一端水合时将其投影为流式行、turn 保持打开——**生成过程中**即可看到 thinking/正文
  以 1–3 秒一拍持续增长，不再误显「已停止」，整轮结束后自动转为完成态。
- 完成与取消写沿用同一数据行覆盖收口，最终结果同步逻辑不变；驱动进程崩溃时，
  进行中标记按新鲜度过期，回落为「已中断」语义。
- 修复会话空闲被运行时驻留池回收后，跨端刷新把会话投影清空的缺陷。

## 验证

- 单元测试 17 项（水合投影 / 心跳策略 / 存储层 / UI 判定链）全部通过。
- 双进程端到端（真实环境、真实 Agent 进程与 WebSocket，零模型调用）三阶段通过：
  冷恢复首帧含进行中正文、外部增量推动新流式帧、完成写收敛为完成态。
- 打包产物 17 项自动断言 + 8 项代码标记扫描全部通过。

## 已知限制

- 流式为**准实时**（1–3 秒一拍），非桌面端本地的 30ms 逐字流；逐字级实时需要
  「手机端附着桌面 Host」的架构（见 spec 后续项）。
- 手机端访问仍**仅限局域网**，不支持公网。
- macOS 安装包仍未提供；命令行命令仍为 `zcode`，数据目录仍为 `~/.zcode`。
